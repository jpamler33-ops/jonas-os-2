# BIGGJ Operator Entry Point

BIGGJ / TCX uses GitHub as the canonical coordination and cross-chat memory layer.

## Single entry point

The open GitHub issue titled:

`[BIGGJ] Project Status`

is the canonical operator index. It is generated from GitHub state and should be
the first status surface read by a new ChatGPT session after `AGENTS.md`.

It contains:

- current default-branch SHA and latest commit
- open parallel pull requests
- recently merged pull requests
- recent GitHub Actions signals
- the mandatory recovery sequence
- the non-negotiable SHADOW_ONLY / ABSTAIN safety invariants
- machine-readable `BIGGJ_PROJECT_STATUS_V1` metadata

## Automatic refresh

`.github/workflows/biggj-project-status.yml` refreshes the issue when:

- `main` receives a push
- a same-repository pull request changes state or head
- an operator manually dispatches the workflow

The renderer is tested before every refresh. If that test fails, the status issue
is not rewritten.

## Relationship to chat handovers

The project-status issue is an index, not a replacement for per-PR handovers.

For implementation detail and unresolved work, use the relevant
`TCX_CHAT_HANDOVER_V1` comment generated by
`.github/workflows/tcx-chat-handover.yml`.

This separation avoids a shared mutable HANDOVER file while still giving every
new session one fast place to recover the current project shape.

## Recovery sequence

1. Read `AGENTS.md`.
2. Read `[BIGGJ] Project Status`.
3. Read the newest relevant PR handover capsules.
4. Inspect overlapping branches before editing.
5. Continue with `inspect -> branch -> small commits -> tests -> PR -> CI -> merge -> live verify`.

The status control plane is coordination-only. It does not alter forecasts,
research authority, model promotion, risk, trading decisions or execution.
